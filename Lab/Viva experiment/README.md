# Simple CMS - Blog Content Management System

## Objective
The objective of this assignment is to design and develop a **Blog Content Management System (CMS)** web application named **Simple CMS** using **Node.js, Express.js, MongoDB (Mongoose), and EJS server-side templates**. 

The application enables users to create blog posts, view a list of all posts with summaries (Title, Author, Creation Date), and open individual posts to read the complete content. All posts are persisted in MongoDB, and creation dates are automatically generated on the backend server.

---

## Technologies Used
- **Runtime Environment:** Node.js (v18+)
- **Backend Framework:** Express.js (v4.21+)
- **Database:** MongoDB (Local or Atlas)
- **Object Data Modeling (ODM):** Mongoose (v8.9+)
- **Template Engine:** EJS (Embedded JavaScript)
- **Environment Management:** `dotenv`
- **Development Tool:** `nodemon`
- **Frontend Styling:** Custom CSS3 with Inter typography and modern responsive layout

---

## Features

1. **Display All Blog Posts (`GET /` or `GET /posts`)**
   - Displays a clean list of all blog posts stored in MongoDB.
   - Shows Title (clickable), Author, and auto-generated Creation Date.
   - **Excludes full content on the list page** to minimize payload size and adhere strictly to assignment requirements.

2. **Create New Blog Post (`GET /posts/new` & `POST /posts`)**
   - HTML form for Title, Content, and Author.
   - **Automatic Creation Timestamp:** Date and time are automatically generated by the server upon post creation; the user does not enter it manually.
   - **Validation:** Validates that Title, Content, and Author are not empty. Displays clear error messages if validation fails.
   - **Redirect:** Automatically redirects to the post list page upon successful creation.

3. **View Individual Complete Post (`GET /posts/:id`)**
   - Displays the full content of a selected blog post retrieved from MongoDB using its unique ID (`_id`).
   - Displays formatted creation date (e.g., `30 September 2026`).

4. **RESTful API Endpoints (`/api/posts`)**
   - Full JSON REST API support for external clients, Postman testing, and mobile apps.

5. **MongoDB Persistence**
   - All blog posts are saved in MongoDB and persist across server restarts or browser refreshes.

6. **Error Handling & 404 Pages**
   - Centralized error handling middleware with user-friendly 404 and 500 error pages for web requests and JSON error responses for API requests.

# HOW TO EXPLAIN THIS PROJECT IN VIVA

This section equips you with clear, student-friendly answers to explain every aspect of this project during your viva examination.

---

### 1. What is Node.js?
**Answer:** Node.js is a free, open-source, cross-platform JavaScript runtime environment that allows developers to run JavaScript code outside of a web browser, on the server side. It is built on Google Chrome's V8 JavaScript engine and uses an event-driven, non-blocking I/O model.

### 2. What is Express.js?
**Answer:** Express.js is a minimal and flexible web application framework for Node.js. It simplifies building backend web applications and REST APIs by providing robust features like routing, middleware support, request/response handling, and template engine integration.

### 3. Why did we use Express?
**Answer:** Without Express, handling HTTP requests, routing, serving static files, and parsing request bodies in raw Node.js requires writing complex low-level code. Express provides clean abstraction, modular routing, middleware chaining, and easy integration with MongoDB/Mongoose and EJS.

### 4. What is a server?
**Answer:** A server is a computer program or software service that listens for incoming network requests from clients (such as browsers or mobile apps), processes those requests (like fetching data from a database), and sends back an appropriate response (such as HTML or JSON).

### 5. What is an API?
**Answer:** API stands for Application Programming Interface. It is a set of rules and protocols that allows different software applications to communicate with each other. In web development, a web API allows a frontend or external application to interact with a backend server.

### 6. What is REST API?
**Answer:** REST (Representational State Transfer) is an architectural style for designing networked applications. A REST API uses standard HTTP request methods (`GET`, `POST`, `PUT`, `DELETE`) to perform operations on resources identified by URLs (endpoints). It typically exchanges data using JSON.

### 7. What are GET, POST, PUT/PATCH and DELETE?
- **GET:** Retrieves data/resources from the server (e.g., fetching post list). It does not modify server state.
- **POST:** Submits new data to the server to create a new resource (e.g., creating a blog post).
- **PUT / PATCH:** Updates an existing resource on the server.
- **DELETE:** Removes a resource from the server.

### 8. What is middleware?
**Answer:** Middleware functions in Express are functions that execute during the request-response cycle. They have access to the Request object (`req`), Response object (`res`), and the `next` middleware function. Middleware can run custom code, validate inputs, parse data, perform logging, or end the request.

### 9. What is `express.json()`?
**Answer:** `express.json()` is a built-in Express middleware function based on `body-parser`. It parses incoming HTTP requests with JSON payloads and attaches the parsed data onto `req.body` so controllers can read input fields easily.

### 10. How does a request reach the server?
**Answer:**
1. A user enters a URL in the browser or submits a form.
2. The HTTP request is sent over TCP/IP to port `3000` where our Node/Express server is listening (`server.js`).
3. Express receives the request and passes it through defined global middlewares (like `express.json()` and `express.static()`).
4. Express matches the requested URL pattern against routes registered in `postRoutes.js` or `apiRoutes.js`.
5. The matching controller action function is executed to handle the request.

### 11. How does the server send a response?
**Answer:** Inside the controller, after processing business logic or fetching data from MongoDB using Mongoose, the controller calls:
- `res.render('viewName', data)` to render an EJS HTML page back to the browser, OR
- `res.status(code).json(data)` to send a JSON payload back to API clients.

### 12. Explain every important file in this project.
- `server.js`: Entry point that initializes MongoDB connection and starts the HTTP server on port 3000.
- `src/app.js`: Configures the Express app, mounts global middleware, view engine (EJS), static files, routes, and error handlers.
- `src/config/db.js`: Establishes database connection using Mongoose `mongoose.connect()`.
- `src/models/Post.js`: Defines the Mongoose Schema & Model for blog posts (`title`, `content`, `author`, `createdAt`).
- `src/controllers/postController.js`: Contains business logic for rendering EJS pages (all posts, create post, single post).
- `src/controllers/apiController.js`: Contains logic for JSON REST API endpoints.
- `src/routes/postRoutes.js`: Defines web URL endpoints (`/`, `/posts`, `/posts/new`, `/posts/:id`).
- `src/middleware/validatePost.js`: Validates input fields to ensure required fields aren't empty.
- `src/middleware/errorHandler.js`: Catches 404 invalid routes and server errors.
- `src/views/`: EJS template files rendered on server side.
- `public/css/style.css`: Modern stylesheet for page styling.

### 13. Explain the complete request-response flow.
**Example: User submits Create Post form (`POST /posts`)**
1. User submits form on `/posts/new`.
2. Request hits Express server (`server.js` -> `app.js`).
3. Express parses form fields into `req.body` using `express.urlencoded()`.
4. Request passes to `validatePost` middleware. If fields are missing, it re-renders form with an error message.
5. If valid, request moves to `createPost` in `postController.js`.
6. Controller creates a new `Post` model instance (`createdAt` generated automatically).
7. Mongoose saves document to MongoDB using `await post.save()`.
8. Controller calls `res.redirect('/posts')` to redirect user back to home list page.

### 14. Explain the database connection if one is used.
**Answer:** We use **MongoDB** as our NoSQL database and **Mongoose** as our ODM (Object Data Modeling) library. In `src/config/db.js`, `mongoose.connect(process.env.MONGO_URI)` establishes an asynchronous connection to `mongodb://127.0.0.1:27017/simple_cms`. Mongoose manages connection pooling, schema enforcement, and query helpers.

### 15. Explain error handling.
**Answer:** We implement centralized error handling. Synchronous and asynchronous errors are caught in controllers using `try/catch` blocks and passed to `next(error)`. In `app.js`, our custom `errorHandler` middleware catches these errors and renders a friendly error page (`error.ejs`) or returns a 500 JSON response if requested via API.

### 16. Likely Viva Questions & Answers (Quick Fire)

1. **Q: How is the post creation date generated?**  
   *A:* It is generated automatically on the backend server by Mongoose schema using `createdAt: { type: Date, default: Date.now }`. The user cannot enter it manually.

2. **Q: Why don't we send complete post content on the list page?**  
   *A:* To optimize network bandwidth and follow the assignment requirement. We use `.select('title author createdAt')` in Mongoose to retrieve only lightweight metadata on the list view. Full content is retrieved on `/posts/:id`.

3. **Q: What is EJS and how does server-side rendering work?**  
   *A:* EJS (Embedded JavaScript) is a template engine. Express compiles EJS templates on the server by injecting JavaScript variables into HTML templates and sends fully rendered HTML to the browser.

4. **Q: What is the purpose of `dotenv`?**  
   *A:* It loads environment variables from a `.env` file into `process.env`, separating configuration settings (like DB URIs and ports) from source code.

5. **Q: What is the difference between `req.params` and `req.body`?**  
   *A:* `req.params` contains route parameters specified in the URL path (e.g. `:id` in `/posts/:id`), whereas `req.body` contains data sent in the HTTP request payload (form fields or JSON body).

6. **Q: What is `nodemon` used for?**  
   *A:* It is a development utility that monitors source code changes and automatically restarts the Node server.

7. **Q: What does `mongoose.model('Post', postSchema)` do?**  
   *A:* It creates a Mongoose model compiled from the schema, providing interface methods like `.find()`, `.findById()`, and `.save()` to interact with MongoDB collections.

8. **Q: What is `process.exit(1)` in database connection?**  
   *A:* It terminates the Node process immediately with a failure exit code if the database connection fails.

9. **Q: What is a 404 status code?**  
   *A:* HTTP 404 indicates that the server cannot find the requested URL resource.

10. **Q: Why use `async/await` in database operations?**  
    *A:* Database operations in Node.js are asynchronous. `async/await` provides clean, readable syntax to handle promises without callback hell.

11. **Q: How does `app.use(express.static('public'))` work?**  
    *A:* It serves static files (CSS, client JS, images) directly to browsers without requiring dedicated route handlers.

12. **Q: What is a Mongoose virtual field?**  
    *A:* A property defined on a schema that is not stored in MongoDB but computed dynamically (e.g., `formattedDate`).

13. **Q: What is the purpose of `res.redirect()`?**  
    *A:* It sends an HTTP 302 redirect response instructing the client browser to navigate to a different URL (e.g. back to `/posts` after creating a post).

14. **Q: How do we prevent empty blog posts from being saved?**  
    *A:* Using validation middleware `validatePost.js` and Mongoose schema `required` field validators.

15. **Q: How do we handle database errors gracefully?**  
    *A:* Using `try/catch` blocks inside async controller methods and forwarding errors to Express error handling middleware via `next(error)`.
